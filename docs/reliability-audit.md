# Аудит надёжности обхода

Дата: 2026-09-14. База: `37ac22c` после интеграции PR #3.
Исходный отчёт: https://github.com/vezlin1/antigravity-bypass-russia/issues/4.

## Что проверялось

Прослежены пути запуска CLI и меню, поиска установок и бинарных профилей,
проверки открытых файлов, резервирования и отката, настройки endpoint,
DNS/DoH, hosts, NRPT и macOS resolver, определения интерфейса, установки
службы, фонового ранжирования, наблюдения за логами и диагностики.
Проверены существующие тесты и сценарии сборки/упаковки.

TLS/HTTP-проверка подтверждает достижимость сервера, а не доступность модели
для аккаунта. `HEAD /` без авторизации может штатно вернуть 401/403/404.
Такой результат нельзя превращать в обещание успешной генерации. Это также
не основание автоматически исключать все маршруты с HTTP 4xx.

## Исправленные сценарии

| Сценарий | Ранее | После изменения |
|---|---|---|
| Региональный отказ при адресе в hosts | Нет недавнего DNS-запроса, IP не исключается | Учитывается фактически установленный собственный hosts-блок |
| Явно указанный remote IP в логе | Требовался DNS-запрос за две минуты | Достаточно однозначного известного маршрута для указанного хоста |
| Долгое соединение или перезапуск службы | Терялась связь с активным IP | Установленные адреса сохраняются и сверяются с hosts |
| Поздняя ошибка старого соединения | Риск обвинить новый маршрут при упрощённом переключении | История смены адреса и защита от серии повторов сохраняются |
| Все альтернативы временно недоступны | Подтверждённо отказавший IP оставался закреплённым | Регионально исключённые pins снимаются; просто временно недоступные сохраняются |
| Неудачный повторный выбор | Ревизия ошибки считалась обработанной до успеха | Необработанный отказ остаётся поводом для следующей попытки |
| Смена интерфейса/шлюза | Использовался сохранённый интерфейс, старые /32 конфликтовали | Интерфейс перепроверяется; перемещаются только точно записанные собственные маршруты |
| Повторная настройка без доступных кандидатов | Сначала удалялась рабочая конфигурация | Рабочая конфигурация не удаляется перед поиском замены |
| Служба не запустилась, включён прямой резервный DNS | Меню показывало полный успех | Показывается частичная настройка без автоматического переключения |
| Диагностика после регионального отказа | Зелёная доступность и общий код успеха | Отказ выводится отдельно, итоговый код неуспешный |
| Медленно поступающий HTTP-ответ | Диагностика могла продлеваться с каждым байтом | Общий срок TCP/TLS/HTTP-проверки |
| DNS не нашёл пригодного ответа | Клиент ждал тайм-аут | Возвращается SERVFAIL |
| Несколько DNS-запросов на macOS | Один медленный запрос задерживал остальные | Четыре рабочих потока, как на Windows |
| Изменённый пользователем resolver | Повторная настройка могла перезаписать его | Сверка с журналом и отказ от перезаписи |
| Неверный адрес в последнем resolver-правиле | Предыдущие правила успевали записаться | Все адреса проверяются до записи |

## Автоматические проверки

Основная команда: `cargo test --locked --bin antigravity-bypass-russia`.
Она запускает изолированные тесты, не включает обход на тестирующей машине.
Старые интеграционные сценарии, которые могут менять ОС, не запускаются
с `--ignored` для проверки этой задачи.

Новые регрессии проверяют путь «новая строка лога → установленный IP →
региональное исключение → выбор альтернативы», миграцию состояния старой
версии, ограничение размера таблицы, неоднозначные/неизвестные адреса,
смену pins и сети, защиту чужих маршрутов и изменений файлов.

Проверки launchers: `python tests/verify_wrappers.py` и
`python tests/verify_macos_bundle.py`. Они используют временные файлы и
тестовый executable. Workflow `Regression checks` запускает проверки на
Windows x64, macOS ARM64 и macOS Intel для PR и веток `main`/`codex/**`.
Успех этих проверок не является проверкой генерации в аккаунте Google.

## Что ещё требуется для подтверждения Issue #4

1. Точная версия Antigravity, обходчика и macOS; локальная работа или Remote SSH.
2. Точная ошибка с несколькими соседними строками, временем и путём журнала.
   Токены, текст запросов и данные аккаунта для этого не нужны.
3. Сопоставление времени ошибки с `network-events.log`, `proxy_rank.conf`
   и установленными адресами. Диагностика теперь показывает, найдены ли
   поддерживаемые журналы языкового сервера.
4. На Mac: запрос к Gemini до/после смены маршрута; затем Claude/GPT,
   перезапуск Antigravity и компьютера, смена Wi-Fi, повторная настройка и откат.
5. Перед релизом: проверка на реальных версиях `agy` и language server,
   включая запуск после подписи. Синтетический Mach-O не заменяет её.

## Ограничения и оставшиеся риски

- Нет подтверждения, что IP провайдера действительно заблокирован Google.
  Нет реального аккаунта/Mac автора для воспроизведения его ошибки.
- Без хоста в строке ошибки нельзя безопасно определить виновный маршрут.
  Такой отказ регистрируется и запускает повторный поиск, но не приводит
  к произвольному исключению адресов всех моделей.
- Поддерживаемые имена файлов и фраза ошибки ограничены в `log_monitor.rs`.
  Новые форматы логов требуют реального примера и отдельной регрессии.
- Ошибка привязана к паре хост/IP, а не к конкретной модели или аккаунту.
  Региональные ограничения аккаунта и внутреннего backend Google не
  устраняются доказанно заменой DNS.
- Открытое соединение может продолжать использовать старый IP после
  обновления DNS/hosts. Программа не разрывает пользовательские сессии:
  для проверки результата может потребоваться перезапуск приложения.
- Если нет пригодных внешних прокси, локальный код не создаёт новый выход
  в поддерживаемом регионе. Нужен доступный провайдер или иной выход.
- Изменение нескольких настроек ОС не является одной атомарной транзакцией.
  Защищены ранний сбой поиска и проверяемые пользовательские изменения;
  отказ записи посередине применения требует диагностики/повторной попытки.
- Сетевой DNS-релей не переносит локальные настройки на Remote SSH-хост.
  Переключение между native/daily endpoint на уже работающем приложении
  также не гарантируется одной заменой IP.
- Системный DNS lookup в диагностике зависит от тайм-аутов ОС; ограничение
  TCP/TLS/HTTP не превращает его в управляемую асинхронную операцию.

Критерий готовности релиза: зелёные платформенные проверки плюс реальный
прогон на Mac. Issue следует закрывать после подтверждения автором, а не
после одной успешной TLS-проверки.
