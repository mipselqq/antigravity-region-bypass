# Antigravity Bypass Russia

Версия: **1.3.0**. [Заметки к выпуску 1.3.0](RELEASE_NOTES_1.3.0.md). Это версия утилиты, а не версия Antigravity.

Утилита для локальных патчей совместимых версий Antigravity и настройки SmartDNS для Google AI на Windows и macOS. Результат зависит от сети, доступности внешних DNS/прокси, версии клиента и серверного допуска аккаунта.

Локальный HTTP/SOCKS-прокси и автопатчер удалены. Сетевой обход работает через DNS; настройки файлов приложения остаются частью обычного включения.


## Запуск

Перед полной разблокировкой, патчем файлов и откатом меню Windows предлагает закрыть Antigravity: 1 — закрыть IDE/CLI и продолжить, 0 — отменить. На macOS приложение нужно закрыть вручную. Команды без интерактивного меню требуют предварительного закрытия приложения. После применения откройте клиент снова. Для изменения файлов установки и системной сети запрашиваются права администратора. Справка, статус и диагностика доступны без повышения прав.

### Windows

Соберите EXE или используйте соответствующую сборку из [релизов](https://github.com/vezlin1/antigravity-bypass-russia/releases).

```powershell
cargo build --release --locked
.\target\release\antigravity-bypass-russia.exe
```

PowerShell 5.1 и PowerShell 7 запускают тот же EXE:

```powershell
.\scripts\unlock_and_restore.ps1
.\scripts\unlock_and_restore.ps1 diagnostics
```

При запуске из исходников обёртка собирает движок, если доступны Rust 1.89+/Cargo и инструменты сборки MSVC. Без Rust положите готовый EXE рядом со скриптом. Отдельного PowerShell-патчера больше нет.

### macOS

Сборка проверяется для Intel и Apple Silicon, но полноценная работа на Mac пока не подтверждена. ARM64 CLI и Universal Mach-O не поддерживаются патчером.

Для сборки нужны Rust 1.89+ и инструменты разработчика Apple. Запускайте сборку от своего пользователя; движок запросит повышение прав для нужной операции.

```bash
cargo build --release --locked
./target/release/antigravity-bypass-russia
# Или через общую обёртку:
bash scripts/unlock_and_restore.sh
```

Для запуска без компиляции положите рядом с `.sh` бинарник `antigravity-bypass-russia-macos-arm64` или `antigravity-bypass-russia-macos-x64`, соответствующий компьютеру, и разрешите его исполнение через `chmod +x`. Скрипт использует тот же Rust-движок.

## Команды

| Команда | Действие |
| --- | --- |
| `unlock` | Патчи обнаруженных файлов, endpoint и настройка DNS |
| `patch-files [путь]` | Патч найденных установок; с путём — только указанных файлов |
| `dns` | SmartDNS, управляемые записи hosts, NRPT на Windows / resolver на macOS |
| `diagnostics` | DNS, TLS с проверкой сертификата/имени и HTTP для трёх endpoint |
| `status` | Текущее состояние обнаруженных компонентов и конфигурации |
| `rollback [путь]` | Отключение обхода и восстановление сохранённых настроек; для CLI приложение нужно закрыть заранее |
| `tune` | Отдельная настройка TCP с предварительным сохранением всех изменяемых значений |
| `--help` | Справка |

Без команды открывается меню. CLI возвращает `0` при завершении запрошенной операции, `1` при ошибке/частичном выполнении, `2` для некорректной команды. Код `0` у диагностики подтверждает только проверенные сетевые этапы.

## Что проверяется

Диагностика отдельно проверяет `daily-cloudcode-pa.googleapis.com`, `cloudcode-pa.googleapis.com` и `generativelanguage.googleapis.com`. Установленное TCP-соединение, TLS Alert или неполный TLS handshake больше не считаются рабочим HTTPS-соединением. Ответы HTTP 401/403/404/429 показываются отдельно от ошибок TLS и 5xx.

Вход в аккаунт, региональный допуск, подписка, квоты и генерация не проверяются запросом `HEAD /`. Их следует проверять в клиенте. Утилита не извлекает токены для этой диагностики.

DNS-релей использует общую таблицу качества по паре «хост + маршрут». Проверяется TCP → TLS с сертификатом и именем → полный HTTP-заголовок; результат свежий 20 секунд. Задержка сглаживается, исправный лидер меняется при преимуществе нового не менее 15%. Это порог переключения, а не обещание прироста скорости.

Первичный поиск использует семь встроенных UDP-адресов SmartDNS, настраиваемые провайдеры и DoH DNS-AI. Для каждого из трёх API-хостов сохраняются до трёх проверенных SNI-маршрутов. Релей сразу отвечает свежим проверенным адресом; устаревшие кандидаты перепроверяются. Фоновый цикл делает паузу 15 секунд, полный поиск — примерно раз в пять минут; продолжительность зависит от сетевых запросов. Транспортные отказы получают возрастающую паузу перед повторной проверкой.

При работающем релее управляемые записи hosts убираются, а правила DNS указывают только на релей: внешние запасные nameserver больше не обходят проверку маршрутов. Если релей не запускается, остаётся прежний режим с hosts и внешними DNS; адаптивные возможности в таком режиме ограничены.

Наблюдатель читает только новые строки журналов language server. Сообщение `User location is not supported` запускает перепроверку; однозначно связанный маршрут исключается на 10 минут. Обычный HTTP 400 не считается региональным отказом. Уже открытые соединения не переносятся, поэтому после смены маршрута может потребоваться новый запрос или перезапуск клиента.

На Windows устанавливается `DoHPolicy=1` и проверяется фактическая NRPT-политика. Отдельный DNS браузера этой настройкой не подтверждается. Конфликтующие чужие правила сохраняются и приводят к сообщению об ошибке.

## Настройка новых сетевых возможностей

`network.json` создаётся при настройке DNS :

- Windows: `%LOCALAPPDATA%\AntigravityBypass\network\network.json`.
- macOS: `~/Library/Application Support/AntigravityBypass/network/network.json`.


После настройки сети в `unlock` принудительный daily-endpoint применяется только при подтверждённом пути к daily и отсутствии проверенного основного Cloud Code. Если основной доступен, собственный override снимается по журналу резервных копий. Пользовательский endpoint сохраняется; без свежих результатов настройки не меняются.

## Совместимость патчера

Поддержка определяется содержимым файла, архитектурой и сигнатурами, а не одним названием продукта. Бинарные патчи ищутся только в секциях кода PE/ELF/Mach-O. Неоднозначные совпадения, неподдерживаемые архитектуры и неизвестные сборки отклоняются. В ошибке несовместимой бинарной версии выводится её SHA-256.

Профили ядра существуют для x64/ARM64; для CLI — только для проверяемой длинной x64-сигнатуры. Универсальные Mach-O и ASAR с integrity-метаданными изменяемого файла пока отклоняются. Подтверждённого каталога всех версий Antigravity нет. Обнаружение установки не означает поддержку каждого её файла.

JSONC-настройки IDE сохраняют комментарии, BOM и посторонние параметры. На Windows прежнее значение и тип пользовательской переменной `CLOUD_CODE_URL` сохраняются перед изменением; новые терминалы получают обновление. Глобальная настройка этой переменной для CLI на macOS не реализована и так и обозначается.


## Откат


Рядом с изменяемым файлом создаётся каталог `<имя>.ag-backups`: оригиналы по SHA-256 и журнал `current.json`. Копия проверяется до записи, файл заменяется атомарно. Откат проверяет соответствие текущего файла журналу. Если приложение обновилось или пользователь изменил настройки, старая копия не записывается поверх них: выводится ошибка, копии сохраняются.

Старый daily-override без журнала снимается отдельно: фактический `settings.json` сначала архивируется, затем удаляется только известный параметр endpoint. Неизвестное прежнее значение не восстанавливается по догадке.

Старый `.bak` применяется только тогда, когда патч этой копии точно воспроизводит текущий файл. Откат без подходящей копии не придумывает исходные инструкции и не удаляет каталог приложения. Для нестандартного пути используйте `rollback "путь"`.

Удаляются только управляемый блок hosts и зарегистрированные маршруты/правила. Сетевые резервные копии остаются в каталоге службы до успешного восстановления, а backup CLI endpoint хранится в `%APPDATA%/AntigravityBypassRussia/cli_endpoint.json`. Пользовательские прокси и сертификаты не очищаются. Новые настройки TCP сохраняются полностью; старый неполный `tcp_backup.conf` относится к прежней версии и сохраняется отдельно. Обычный откат DNS его не применяет и не сбрасывает неизвестные параметры к стандартным. Отсутствие этих старых значений не мешает отключить текущий обход; при этом программа сообщает, что старые настройки сети остались. Ошибки актуального `tcp_snapshot.json` по-прежнему приводят к неуспешному откату. Это не мешает повторно настроить DNS.

## Проверки разработчика

Проверки используют временные файлы, синтетические бинарники и loopback. Они не применяют обход к системе:

```bash
cargo test --locked --bin antigravity-bypass-russia -- core:: system::journal::tests system::privilege::tests system::file_lock::tests net::health::tests net::rank::tests net::resolvers::tests net::doh::tests net::hosts::tests net::config::tests net::client::tests net::dns_https::tests net::log_monitor::tests net::route_health::tests net::tests tcp_snapshot_must dns_rollback_ignores
python tests/verify_wrappers.py
cargo build --release --locked
```

CI содержит сборки Windows x64, macOS ARM64 и macOS Intel. Проверки на реальных установках и авторизованную генерацию нельзя заменить этими тестами.
